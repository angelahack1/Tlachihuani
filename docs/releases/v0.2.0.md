# Tlachihuani 0.2.0

3 November 2026 · Windows x64

This release packages the primary service, the Jobs host, XT and the controller in a graphical Windows installer. The matching uninstaller removes the registered services, shortcuts and packaged files while retaining the protected Jobs journal, account identities and downloaded files.

## Install and start

Follow the [Windows setup guide](../../packaging/setup/README.md). Build output is in `artifacts/setup/0.2.0/windows-x64/`. Keep both executables together. Each wizard shows the version before asking to make changes. The service heartbeat and wizards take their version from the build. The REST contract remains **v1**.

After installation, open **Tlachihuani XT**. If it is missing from the notification area, launch the installed tray executable with `--show` as described in the [README](../../README.md#first-download). Open the gray icon’s menu and choose **Start Services**. A green icon and `{"api_version":1,"engine":"ready"}` from the local health endpoint confirm that Torrenter is available. In Tlamatini, **Panels → Torrenter Workspace** shows the signed-in account.

## Existing installations

- **Wizard-managed 0.1.0:** stop the services, exit XT and uninstall with the matching 0.1.0 uninstaller. Run the 0.2.0 installer as the same operator to reuse the retained state.
- **PowerShell-managed:** follow the [legacy packaging instructions](../../packaging/windows/README.md). Back up the old program and state directories before starting fresh. A renamed legacy journal remains available for recovery and is not automatically imported.

## Verification scope

For 0.2.0, the locked Release build passed all 11 lifecycle checks, including a real console-host heartbeat and graceful shutdown. Both shipping wizards opened visibly, displayed 0.2.0 and passed Review and Cancel. The cabinet audit compared all 133 bundled runtime files byte for byte with the published build. This release check did not install over the running workstation installation.

The previous 0.1.0 acceptance run exercised install, service start, uninstall, retained identity, reinstall and removal using separately named QA services. On the operator’s workstation the production 0.1.0 wizard completed installation after legacy files were backed up. The operator then confirmed XT startup, API readiness and the signed-in workspace. These observations describe the installation actually tested.

The [setup test commands](../../packaging/setup/README.md#reproduce-a-build) cover wizard review, isolated Windows Installer transactions and a disposable guest with the production Jobs service. The local executables are unsigned.
