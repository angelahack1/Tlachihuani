## Download, extract, install

Run **`Build-Release.cmd`** from the repository root in a visible Command Prompt.
Each invocation selects the highest numeric stable local Git tag, stamps product
versions and rebuilds the current checkout in fresh staging. It runs lifecycle,
MSI payload and ZIP integrity checks before producing
`dist/Tlachihuani-0.2.1-windows-x64.zip`
and a matching `.zip.sha256`. The ZIP contains Installer.exe, Uninstaller.exe,
START-HERE.html, READ-ME-FIRST.txt, manifest.json and SHA256SUMS.txt.

The guide is styled for Tlachihuani and works offline. Extract the ZIP with
Windows **Extract All**, open Installer.exe, choose whether XT should appear at
Windows sign-in, review the operator, destination and choice, then install.
The normal unelevated wizard opens XT once after success. Start and Desktop
shortcuts always reopen it and the overview. The optional common login shortcut
remains tray-only. Both services stay stopped/Manual after installation and reboot;
the operator chooses **Start Services** when needed.

All four executables are published self-contained for Windows x64. Private
.NET runtimes and the verified CPython/libtorrent runtime travel in the MSI.
Clients do not install a separate .NET runtime, SDK, Python or WiX. There is
no single-file runtime extraction into a user profile. The build refuses
framework-dependent payloads before producing setup.

## Windows integration

Windows Installer owns one per-machine Programs and Features / Installed apps
entry. It supplies the name, version, XAIHT publisher, estimated size, cached
XT icon and native uninstall command. Setup supplies installation location,
help/about links and contact details. Modify/Repair are disabled, Uninstall
remains available. No duplicate manually maintained uninstall entry is created.

Application discovery values under `HKLM\Software\XAIHT\Tlachihuani` include
InstallLocation, Version, OperatorSID and TrayAtLogin. MSI removes these values, its shortcuts,
services and packaged files. Downloads, exports, protected identities and the
Jobs journal remain. The cached MSI supports removal after the download ZIP
has been deleted. Native removal stops running services through ServiceControl
instead of refusing them before the stop action. Close XT before removal to
avoid files-in-use handling or a possible restart.

The installed application includes the matching uninstaller and offline guide.
Start offers XT, the guide and a native **Uninstall Tlachihuani** shortcut.
Upgrades from older versions remain remove/reinstall as the same operator;
this update does not introduce in-place upgrades or migrate renamed legacy queues.

## Verification scope

See [implementation status](../implementation-status.md) for the dated outcome.
The acceptance harness checks a separately named QA MSI through real install,
SCM start, native registered removal and reinstall, retaining its identity.
Production-payload checks separately cover ZIP integrity, all cabinet bytes,
self-contained runtime configuration and visible shipping wizard review.
The Sandbox path maps no host .NET runtime into the guest.

The binaries are unsigned. Authenticode requires the publisher's certificate;
checksums are integrity checks, not a replacement for publisher signing.
No Tlamatini source or installed production service is changed by these tests.
